# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this project is

`gameX` is a greenfield project to design and build *Tide / Pull*, a cosy one-button physics game (working title; rename pending). The first three phases — concept, design, tech plan — produced specs in `docs/specs/`. The build phase is unblocked; the slice runs at `http://localhost:5173/` once `npm run dev` is up under `game/`.

This CLAUDE.md describes the **team and workflow**. Once meaningful game code exists, the game's directory (under `game/`) may want its own CLAUDE.md generated by `/init` against the actual code; for now this file is the source of truth.

## The workflow

Each phase produces a committed artefact in `docs/specs/`. Phases 0 → 1 → 2 each end with a user checkpoint. Phase 3 runs day-by-day with checkpoints at the four ⛳ gates from the tech-plan.

| Phase | Driver | Input | Output |
|---|---|---|---|
| 0 — Concept | `creative-director` (via `/concept-pitch`) | optional nudge | `docs/specs/YYYY-MM-DD-premise.md` |
| 1 — Design | 6 specialists (via `/creative-council`) | premise | `docs/specs/YYYY-MM-DD-<topic>-design.md` |
| 2 — Tech plan | `tech-lead` (via `/tech-plan`) | design spec | `docs/specs/YYYY-MM-DD-tech-plan.md` |
| 2.5 — Pipeline adapter | orchestrator (one-time) | tech-plan | `docs/specs/2026-05-06-build-pipeline-adapter.md` |
| 3 — Build | `dev-agent` + `qa-agent` + `reviewer` (per tech-plan day) | tech-plan day blocks | committed code on `main` + `docs/specs/build-log.md` |
| 4 — Slice handoff | user (post-stranger-test, day 10) | working slice | next-step decision (continue / ship / deprecate) |

The Phase-3 loop is `day block → dev → QA → reviewer → next day block`. No PRs, no remote, no merge. See `docs/specs/2026-05-06-build-pipeline-adapter.md` §Workflow shape for the loop in detail.

## Slash commands

| Command | Purpose | Phase |

## Constraints that survived generalisation

These conventions came from the prior project this scaffold was based on and have been kept because they make the team work well:

- **Australian English** in synthesis text, draft consensus, and spec text.
- **No dark patterns by default.** Streak counters, guilt nudges, gacha, loot boxes, and exploitative engagement loops are off. The `habit-formation` specialist holds the line. The Tide / Pull design spec items 21–33 are the concrete ban list for this game.
- **Parallel dispatch when fanning out.** When the council runs a round, it dispatches all six specialists in a single message with parallel `Agent` calls. Sequential dispatch is a bug.
- **Hard cap of 4 rounds** in the council.
- **Neutral-sibling user checkpoints.** No "recommended" labels at choice points. No token-cost callouts.
- **Ethics override is documented, not silent.**

## What's deferred

- **GitHub integration.** No remote, no `gh`, no MCP server for GitHub. The slice runs locally. If the game ships, a remote gets set up at the slice-handoff step.
- **Hooks at `.claude/hooks/`.** None configured. Conventions are enforced at review time by the `reviewer` agent, not at write time.
- **Phase 4 / post-slice work** — to be decided at the day-10 stranger-test checkpoint.

## What this CLAUDE.md is NOT

It's not the game's CLAUDE.md. Once `game/src/` is large enough to have its own conventions worth documenting in-place, run `/init` against it. This file remains the orchestration team's reference.

## Quick reference for new sessions

If you're a fresh Claude session opening this repo, the answer to "what should I do?" depends on what's in `docs/specs/`:

- **No `docs/specs/` files** — workflow hasn't started. The user runs `/concept-pitch`.
- **Premise only** — Phase 1 next. User runs `/creative-council <premise>`.
- **Design spec, no tech-plan** — Phase 2 next. User runs `/tech-plan`.
- **Tech-plan, no adapter, no code** — Phase 2.5 next. Orchestrator writes the build-pipeline adapter.
- **Adapter + tech-plan, no `game/` directory** — Phase 3 day 1: dispatch the dev-agent against tech-plan day 1.
- **`game/` directory exists with code** — Phase 3 in progress. Read `docs/specs/build-log.md` to find the latest day; dispatch the next agent in the loop.
- **All ten days complete** — Phase 4 / slice-handoff checkpoint.
