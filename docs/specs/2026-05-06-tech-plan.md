## 1. Stack choice and rationale

### Pick

| Concern | Choice | Version | Why this, here, now |
|---|---|---|---|
| Language | TypeScript | 5.6+ | Type-safety pays for itself the moment the fluid sim's grid indices and lunar-phase enums start crossing module boundaries. Pixi v8 is written in TS; types come for free. |
| Renderer | **Pixi.js** | 8.18.0 | Spec mandates it (Proposed Changes #1, #4, #12). v8 is mature, WebGL/WebGPU dual-renderer, single npm package, no separate type packages. |
| Build / dev server | **Vite** | 8.0.10 | Fast HMR is non-negotiable when iterating on fluid-sim feel for 60+ seconds at a time. Rolldown bundler stable since March 2026. `npm create vite@latest` scaffolds in one command on Windows. |
| Audio | **Web Audio API direct**, with Howler 2.2.4 as a **fallback only** | native | The spec needs **per-phase low-pass filter automation on a single ambient bed** (Proposed Changes #9). That's `BiquadFilterNode` + `AudioParam.linearRampToValueAtTime` — three lines of native Web Audio. Howler is a playback library; its filter story is "expose `Howler.ctx` and write Web Audio yourself." So we'd be writing Web Audio either way. Skip the wrapper, save the dependency. If browser autoplay-policy or sample-decode pain shows up by day 5, fall back to Howler for playback only and keep our own filter graph. |
| Persistence | `localStorage` | native | Slice scope is "bay state across three nights of one session." Single JSON blob keyed `tide-pull/save/v1`. IndexedDB is overkill for a single object under 50 KB. |
| Test approach | **None automated for the slice.** Manual feel-testing only. | — | Two weeks, solo, the unit under test is "does pulling water feel good." Vitest scaffolding for the JSON loader spec is the only place automated testing would earn its keep, and even that is P3. |
| Linter / formatter | ESLint 9 flat config + Prettier | latest | Default Vite TS template ships these. Don't deviate. |
| Trailer capture | **OBS Studio** (already common on Windows) or browser DevTools "Capture screenshot" + `MediaRecorder` API for in-page capture | — | OBS is the Windows default for clean 1080p60 capture. Document the OBS scene config; do not build an in-game recorder. |

### Alternatives considered and rejected

- **Phaser 3.x** — heavier, opinionated scene/state stack we don't need, and its arcade physics doesn't help with bespoke fluid sim. Pixi is the lighter primitive — we want the renderer and nothing else.
- **Three.js** — overkill for top-down 2D. WebGL 2D draws are exactly what Pixi exists for.
- **PixiJS React v8** — adds a render-tree abstraction we'd have to fight when implementing imperative 60fps fluid-sim updates. Skip.
- **Godot 4** — viable Windows install, would give a built-in scene tree and fluid samples, but the spec is explicit about Pixi/WebGL and the Steam-via-browser distribution path. Switching engines costs 1–2 days of the 10 we have.
- **Bare canvas + no Pixi** — possible but throws away v8's batching, sprite-pooling, and the `Container`/`Sprite` graph that lets the cursor-as-moon and reduce-motion swap rules stay one-line changes.

### Where state, rendering, input, assets live

- **State:** `src/state/gameState.ts` is a plain TS object with a typed shape. No Redux, no signals library — solo dev, ten days, one screen of state. Mutations are explicit functions: `enterNight(n)`, `markCompleted(n)`, `softDrift()`. The gamestate object is what `save.ts` serialises.
- **Rendering:** Pixi `Application` in `render/stage.ts`. Three top-level `Container`s: `bgLayer` (water + bay), `entityLayer` (boats, lanterns, debris), `uiLayer` (cursor moon, title card). Cursor is on `uiLayer` so it always renders above everything — and so it's in any window-capture frame (clip-render acceptance criterion).
- **Input:** one `pointer.ts` module attaches `pointermove` / `pointerdown` / `pointerup` to the canvas. Outputs a small struct `{ x, y, holding, holdMs }` consumed each frame by the sim. Reduce-motion query lives next to it because both are platform-edge concerns.
- **Assets:** `public/audio/` and `public/sprites/` — flat directories, kebab-case names (`cursor-moon-waxing.png`, `ambient-bed.ogg`). Pixi v8 `Assets.load()` for sprites; the `AudioContext` decode for audio. Five audio files total per spec.

### Save / persistence

- One `localStorage` key: `tide-pull/save/v1`. Single JSON blob: `{ completed: { 1: bool, 2: bool, 3: bool }, bayDelta: { items: [...] }, version: 1 }`.
- Versioning the key now (`v1`) is one line and prevents the inevitable schema break later. Migration is out of slice scope (deferred).
- Spec items 22, 27 enforce: no real-world date written to save, no notification scheduling, no streak field.

### What is intentionally NOT designed yet

The slice is one bay, three nights, single session. We are deliberately not designing: a content pipeline for additional bays, an asset-baking step (sprites are PNGs, not atlased), a Steam SDK integration, a save-migration pathway, a level-editor schema, anything to do with itch.io or Steam upload, network code of any kind, accessibility beyond the spec's three named items (reduce-motion, contrast, cursor-in-frame). Each of these is a week's work on its own and will compound if smuggled into the slice.

## 3. Vertical-slice scope

### In scope (mapped to spec acceptance criteria)

1. One persistent bay, top-down, internal 1920×1080, Pixi v8 / WebGL on `<canvas>` *(spec §Proposed-Changes #1)*
2. Three nights, three lunar phases — abstract in-game cycle, NOT real calendar *(#2, ethics item 27)*
3. Pull strength + radius parameterised on lunar phase: 0.7×/80px, 1.0×/140px, 0.85×/110px *(#2, acceptance "Pull strength scales with lunar phase")*
4. Cursor IS the moon: Pixi sprite, three variants, OS cursor hidden via `canvas { cursor: none; }` *(#4, acceptance "Clip-render")*
5. Three goals: guide (N1), gather (N2), third verb (N3 — see §6) *(#3)*
6. Soft-drift failure model — ease-out 1.2s, ambient duck 4dB, cursor 60% opacity, no modal/button/counter *(#5, acceptance "Soft-drift failure")*
7. Sandbox / free-pull mode unlocked from first run, doubles as title bg *(#6, also the 60-second feel-test surface for Goal 1)*
8. Moonrise opening: 6–10s first launch, 1.5–2s returning, skippable from frame 1 *(#7, acceptance "First launch" / "Returning launch")*
9. Three-second lunar-phase title card per night, fade 400ms, no other on-screen text *(#10)*
10. Audio: 1 ambient bed + per-phase low-pass filter automation + 4 SFX + 1 release-swell variant *(#9)*
11. Reduce-motion: `matchMedia('(prefers-reduced-motion: reduce)')` plus `change` listener; defined swap rules *(#11)*
12. Clip-render: cursor sprite at pointer, OS cursor hidden, captures cleanly *(#12)*
13. Persistent bay state across nights via base + delta JSON merge *(#15)*
14. Linear ordering on first playthrough; free-pick after first completion; no padlock iconography ever *(#2 last sentence, acceptance "First-playthrough ordering" / "Free-pick after first completion")*
15. WCAG 1.4.11 (3:1 non-text contrast) for floating objects against worst-case water tile *(#8)*
16. Wordless 30-second trailer cut by end of week 1 *(#18, Goal 7)*
17. Healthy first session: 8–12 minutes, no "play again?" pop-up *(#20, acceptance "Cosy session shape")*
18. Hard ethics perimeter (items 21–33): enforced by *absence* — no telemetry SDK installed, no notification API call, no leaderboard module, no real-money flow, no in-game share UI

### P3 — explicitly cuttable for time

Each of these has a concrete cut-condition. If we hit it, the item is gone, no agonising.

- **P3a — Cursor velocity-driven phase shadow rotation** *(spec #4 last sentence)*. If the sim spike eats day 3 plus day 4, cut. Cosmetic; the cursor still phases statically.
- **P3b — Cursor-trail at low opacity for compressed-video legibility** *(spec #12 last sentence)*. Cut if not in by end of week 1; trailer can compensate via OBS scene composition.
- **P3c — Ambient creatures in sandbox / first-pull surface (gulls, distant whale)** *(council R1 storyboarder P3)*. Cut if not in by end of day 8. Sandbox still works without them.
- **P3d — Drop-shadow / rim-light pass on every floating object as separate sprite layer.** Cut to flat sprite + colour-contrast tuning if rendering perf shows up as an issue.
- **P3e — Audio fallback already lives in spec #14**: drop one SFX, keep bed + swell + 3 SFX. This is the day-5 gate's pre-decided cut.

### "The slice is done when…" — testable criteria

The slice is done when **all of the following hold simultaneously on a fresh Windows browser load** (Edge or Chrome, latest):

1. A stranger who has never seen the game opens the URL and, *without any prompt or instruction*, plays unprompted for ≥60 seconds. *(Goal 1)*
2. The same stranger, when invited to "play through the three nights," completes all three within 8–12 minutes with no fail screens, no pop-ups, no on-screen text other than the three title cards. *(acceptance "Cosy session shape")*
3. Pull strength is *measurably* greater on Night 2 than on Nights 1 and 3 — tested by repeating an identical 1-second hold over the same water tile and observing different displacement. *(acceptance "Pull strength scales with lunar phase")*
4. Bay state from Night 1 visibly persists into Night 2; from Nights 1+2 into Night 3. *(acceptance "Persistent bay across nights")*
5. Soft-drift fires the camera ease-out + ambient duck + cursor dim, and the next press-and-hold re-engages without any modal/button. *(acceptance "Soft-drift failure")*
6. With OS-level reduce-motion enabled, moonrise is an instant cut + 400ms fade and release rush is the 200ms opacity+scale tween. *(acceptance "Reduce-motion")*
7. A screen recording (OBS, full-screen-window source) shows the moon-cursor in every frame.
8. The game has zero outbound network requests after initial asset load. (DevTools Network tab, filter "fetch/xhr", confirm empty.)
9. The 30-second wordless trailer renders correctly in a muted browser playback.

## 4. Build sequence

**Format:** `Day N — Title (S/M/L) [⛳ checkpoint if applicable]`. Estimates assume solo dev with AI assistance. Two-week slice = 10 working days; days 11–12 are slack/polish.

---

### Day 1 — Project bootstrap + Pixi "hello bay" (S → M)

- **Build:** `npm create vite@latest game -- --template vanilla-ts`; install `pixi.js@^8.18.0`; render a solid-colour rectangle at 1920×1080 internal, fit-to-window, with `cursor: none` on canvas; place a circle sprite that follows `pointermove`. Verify `npm run dev` opens at `http://localhost:5173/`.
- **Depends on:** nothing.
- **Done when:** moving the mouse moves a circle on a coloured background and the OS cursor is invisible over the canvas.
- **Cost:** S.

### Day 2 — Motion-and-colour bible + level loader skeleton (M)

- **Build:** Author `docs/specs/2026-05-05-motion-bible.md` (timings, palette stops, shape vocabulary — already specified in spec §8, just transcribe to a working doc). Implement `level/loader.ts`: read `bay.base.json` + one `night-N.delta.json`, merge, return typed `LevelDef`. Stub the three night JSON files with one floating object each.
- **Depends on:** Day 1.
- **Done when:** loading Night 1 places one boat sprite on the bay; loading Night 2 places lanterns; loading Night 3 places the third-verb receiver.
- **Cost:** M.

### Day 3 — ⛳ FLUID-SIM SPIKE + KILL GATE (L)

This is the day. Spec items #13 and Risk #1 both ride on it.

- **Build:**
  - **Default approach:** cellular-automaton water on a coarse grid (~96×54 cells covering the 1920×1080 playfield). Each cell holds height + horizontal-flow vector. The pull force is `force = phasePullStrength × falloff(distance, phaseRadius)`, applied to flow vectors of cells inside `phaseRadius` of the cursor when `holding === true`. Render as a `Pixi.Mesh` with a height-coloured palette OR as a dense `Graphics` heightmap. Tune until pull feels physical.
  - Sandbox mode = this surface, no objects, no goal.
- **Depends on:** Day 1 stage + cursor.
- **Done when (the gate):**
  1. **Self-test ≥60 seconds at full moon (1.0×/140px) with no goal — and you want to keep going.** *(spec #13)*
  2. **Pull strength + radius parameterise cleanly: switching `phasePullStrength` from 0.7 → 1.0 → 0.85 produces visibly and feel-ably different surface response.** *(spec #13)*
  3. A second tester (anyone available — non-dev) does the same thing, reports "this is fun" or equivalent, *unprompted, without explanation of what they're doing*.
- **If the gate fails (pivot to second-choice):** stop the cellular automaton and switch to `sim/particles.ts`: a height-field/SPH-lite particle system. ~200–400 small particles representing water "blobs," softly attracted to the cursor on hold, returning to rest position via spring force on release. Render as alpha-blended Pixi sprites in a `ParticleContainer` (Pixi v8's GPU-batched container). This trades fluid realism for predictable feel and is roughly half the implementation cost of getting cellular-automaton tuning right. The pivot decision must be made by **end of day 3**. Do not let the spike bleed into day 4.
- **⛳ User checkpoint:** Show a screen-cap of the working surface to the user. Confirm: "this is the water for the rest of the slice."
- **Cost:** L (planned full day).

### Day 4 — Verb 1: guide (boat to harbour) + soft-drift skeleton (M)

- **Build:** `verbs/guide.ts`: a paper-boat sprite obeys the local flow vector each frame. Define a "harbour" rectangle on N1's bay; "goal met" when boat enters and remains for 1.5s (held-success beat from spec #5 + R1 storyboarder P2). Implement `softDrift()`: camera ease-out (Pixi `stage.scale` lerp), ambient duck (gain ramp), cursor opacity 1.0→0.6, receiver respawn after 1.2s.
- **Depends on:** Day 3 fluid sim, Day 2 loader.
- **Done when:** Night 1 plays end-to-end. Holding pulls water, water drifts the boat, releasing lets currents settle. Boat reaches harbour → 1.5s held-success beat → night ends. Letting boat drift off-screen → soft-drift triggers, no modal, no button, next press-and-hold re-engages.
- **Cost:** M.

### Day 5 — ⛳ AUDIO SCOPE GATE + ambient bed + filter automation (M)

- **Build:** `audio/manager.ts`. Boot `AudioContext` on first user gesture (browser autoplay policy). Load and decode 5 audio files. Wire ambient bed → `BiquadFilterNode` (lowpass) → `GainNode` (master) → `destination`. Per-phase filter cutoff: 800Hz (waxing) → 2kHz (full) → ~1.4kHz (waning). Use `linearRampToValueAtTime` over 1.5s on phase enter. Wire 4 SFX one-shots, plus the release-swell variant (re-pitched, longer tail) on the climactic release of each night.
- **Done when:** all 5 cues fire on the right events; switching nights audibly shifts the filter in real-time.
- **⛳ Audio scope confirmation gate (spec #14):** if filter automation isn't shipping cleanly by end of day 5, exercise the documented fallback — drop one SFX, keep bed + swell + 3 SFX, no per-phase differentiation. Document the choice in the build log either way.
- **⛳ User checkpoint:** Show + sound-check N1 with audio. Confirm: cosy reads correctly.
- **Cost:** M.

### Day 6 — Verb 2: gather (full moon, lunar inversion) (M)

- **Build:** `verbs/gather.ts`. Spawn ~12 floating objects (per spec #3 — lanterns or driftwood) on N2's bay. Press-and-hold pulls them along the flow field; cluster within ~60px of cursor for 1s = goal met. Phase to full moon: 1.0× pull / 140px radius / cursor sprite swap to full-moon disc (32px, halo). Persist N1's wreck (if any) into N2 via the delta-layer overlay.
- **Depends on:** Day 4 verb pattern.
- **Done when:** N2 plays end-to-end. The full-moon strength is *audibly and visibly* greater than N1.
- **Cost:** M.

### Day 7 — Verb 3 (the unresolved one) + ⛳ Trailer cut (L)

- **Build:**
  - The third verb: **provisional pick = "send" (paper lanterns).** Reasoning in §6. Implement `verbs/settle.ts` (file name kept generic) for whichever verb wins. Concrete picture for "send": ~6 lantern sprites lined on the headland, lift on hold, ride the flow vector outward on release, "goal met" when ≥4 reach the bay's far edge. Persist N1 wreck + N2 lantern-cluster into N3.
  - **Trailer cut.** OBS scene: full-screen browser, mic off, system audio capture. Record the 30-second sketch from spec #18 — black + sustained note + title (3s) → moonrise (3-4s for trailer) → cursor appears (1s) → first hold + lift (3s) → release + chime (3s) → cut to N2 (3s) → cut to N3 phase tint (3s) → three-up phases freeze frame (5s) → wishlist CTA card (3s, **trailer asset only, not in game**).
- **Depends on:** Day 4–6.
- **Done when:** N3 plays. Trailer 30s render exists at `docs/specs/trailer-cut-1.mp4` (or equivalent path) and reads correctly muted.
- **⛳ User checkpoint:** Trailer review + third-verb confirmation. If "send" wasn't the right call, swap to "settle" or "extinguish" — see §6 for what each costs.
- **Cost:** L.

### Day 8 — Persistence + night picker + linear/free-pick logic (M)

- **Build:** `state/save.ts`: read/write `tide-pull/save/v1`. `scenes/nightPicker.ts`: three lunar-phase glyphs as buttons, no padlocks, no completion ticks; first run greys out N2/N3 (greyed = not selectable, *not* padlocked); after first full-slice completion, all three are selectable. Persist `bayDelta` so Night 2's lanterns reappear if player picks N3 freely.
- **Depends on:** Days 4–7.
- **Done when:** Quitting and reopening preserves which nights are completed and the bay deltas. Acceptance "First-playthrough ordering" + "Free-pick after first completion" pass.
- **Cost:** M.

### Day 9 — Reduce-motion path + WCAG contrast pass + clip-render verification (M)

- **Build:**
  - `a11y/reduceMotion.ts`: `matchMedia('(prefers-reduced-motion: reduce)')`, `change` listener. Wire swap rules from spec #11 — moonrise instant cut + 400ms ambient fade; release rush replaced by 200ms opacity 1→0.6 + scale 1→0.98; cursor-trail damped/omitted.
  - WCAG 1.4.11 contrast audit: sample worst-case water tile colour per phase (darkest cell of the heightmap palette) and verify ≥3:1 against every interactive sprite. Adjust rim-light or drop-shadow as needed.
  - Clip-render verification: OBS recording, then Edge DevTools → Capture screenshot, both showing the moon-cursor in the captured frame.
- **Depends on:** all prior days.
- **Done when:** OS reduce-motion toggle on/off mid-session changes behaviour on next animation. Contrast checked. Capture clean.
- **Cost:** M.

### Day 10 — ⛳ Stranger-test + slice complete (M)

- **Build:** Polish pass. Fix anything broken from days 1–9. Write `docs/specs/build-log.md` capturing what shipped vs P3-cut.
- **Stranger test (spec acceptance "Cosy session shape" + Goal 1):** find one human who has not seen the game. Open the URL on this Windows machine. Hand them the mouse. **Don't speak.** Time how long they engage. Acceptance = ≥60s unprompted in sandbox; full slice playable in 8–12 min.
- **Depends on:** all prior days.
- **Done when:** stranger test passes OR documented fail with named cause.
- **⛳ Final user checkpoint:** Slice review with the user. Hand off to Phase 3 (which is already deferred per CLAUDE.md until the build pipeline gets adapted for greenfield local).
- **Cost:** M.

### Days 11–12 — Slack / contingency (built-in)

- Buffer for the day-3 fluid pivot, the day-5 audio fallback, or any council follow-up.
- If unused: title rename research and Steam-page mock from spec §16 (still pre-public, no commits to a remote).

## 5. Risks and mitigations

Carrying forward the spec's R4 risk register, refined for stack and build order:

1. **R1 — Fluid sim doesn't parameterise cleanly per phase or doesn't *feel* hypnotic** *(high × high)*. Day-3 kill gate is the mitigation. Second-choice approach (SPH-lite particles) named, scoped, and architected as a parallel module so the pivot is a swap, not a rewrite. **Cap the cellular-automaton attempt at one full day.** Don't grind on day 4.
2. **R2 — Audio scope creep, filter automation eats time** *(medium × high)*. Day-5 gate. Pre-decided fallback (drop one SFX, no per-phase filter). Audio is one ambient bed plus four shots — Web Audio API, not a wrapper, removes the dependency surface where this could go wrong.
3. **R3 — "Cosy" reads as "low-contrast / unreadable"** *(medium × high)*. Motion-and-colour bible written day 2 *before* sim work; WCAG 1.4.11 audit on day 9; rim-light/drop-shadow on every floating object. Audit can fail late and force art rework — mitigate by colour-picking against the *already-rendered* darkest water tile, not the average.
4. **R4 — Two-week scope overruns** *(high × high)*. P3 list (3a–3e) is the named buffer. Days 11–12 are slack. The kill gate on day 3 protects the back half of the schedule.
5. **R5 — Extinguish-style or "send"-style verb tuning falls flat at the *kishōtenketsu ten*** *(medium × medium, new from spec R4 risk #3 generalised)*. The gradient-feel of N3 must be forgiving, not punishing. Tune in the same window as N1 soft-drift on day 4 — share the threshold logic.
6. **R6 — Steam autoplay-muted trailer doesn't carry the wedge silently** *(low × high)*. Trailer cut by day 7 leaves three days to re-record. OBS scene config + fixed dev-session capture means re-records are cheap.
7. **R7 — Browser autoplay policy gates audio on launch** *(low × medium, stack-specific)*. Standard mitigation: defer `AudioContext.resume()` until first user gesture (`pointerdown`). Wire on day 5; trivial. Surfacing because solo devs sometimes hit this on day 9.

## 6. What this plan does NOT cover

### Items deferred from the design spec

- **Title rename ("Tide / Pull" → final).** Spec #19 + Open Question 2. Deferred to end of Phase 2 per spec. Days 11–12 slack can host a 30-minute Steam search test, but no public commit happens in the slice anyway.
- **Steam page art / capsule / store CTA.** Out of slice. The trailer is the only Steam-aimed artefact in scope.
- **itch.io upload, Steam upload, distribution of any kind.** Slice runs on `localhost:5173/`. Deployment is post-slice.
- **Save migration.** `v1` keying makes the future migration possible; no migration code in the slice.
- **Mobile / touch port.** Deferred (spec non-goal #8, item #37).
- **Daily-seed sandbox, bays gallery, level editor, swimmers, weather, kishōtenketsu fourth night, real-world lunar tie-in.** All deferred per spec items 34–40.
- **Asset pipeline.** Sprites are hand-PNGs, audio is hand-OGGs+MP3s. No atlas baking, no audio sprite generation, no Aseprite tooling integration.
- **Localisation.** No on-screen text means no l10n needed in slice. Lunar-phase title-card text is one of three English strings; if l10n becomes a thing post-slice it's a one-day job.
- **Test automation.** No Vitest, no Playwright, no Jest. Manual feel-testing only.
